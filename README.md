# TODO-планировщик

Планировщик задач на Go с SQLite, веб-интерфейсом и REST API. Поддерживает создание, просмотр, редактирование, завершение и удаление задач, повторения, поиск и JWT-аутентификацию.

## Архитектура

```text
.
├── main.go
├── go.mod
├── go.sum
├── Dockerfile
├── .dockerignore
├── pkg/
│   ├── api/
│   │   ├── api.go
│   │   ├── auth.go
│   │   ├── signin.go
│   │   ├── task.go
│   │   ├── addtask.go
│   │   ├── gettask.go
│   │   ├── edittask.go
│   │   ├── donetask.go
│   │   ├── deletetask.go
│   │   ├── tasks.go
│   │   ├── nextdate.go
│   │   ├── response.go
│   │   └── *_test.go
│   ├── db/
│   │   ├── db.go
│   │   ├── task.go
│   │   └── tasks.go
│   └── server/server.go
├── tests/

```

`pkg/api` обрабатывает HTTP, проверяет данные, вычисляет даты и проверяет JWT. `pkg/db` инициализирует SQLite и выполняет параметризованные SQL-запросы. `pkg/server` настраивает HTTP-сервер и раздаёт файлы `web`. `main.go` сначала открывает БД, затем запускает сервер.

## Задания со звёздочкой

Реализованы `TODO_PORT`, `TODO_DBFILE`, правила `w` и `m`, поиск по заголовку, комментарию и дате, JWT и Docker.

Повторения: `d N` (1–400 дней), `y` (год), `w 1,3,5` (дни недели от понедельника до воскресенья), `m 1,-1 2,8` (первый и последний день февраля и августа). Для `m` допустимы дни 1–31, `-1` и `-2`; список месяцев необязателен.

Поиск по тексту учитывает кириллицу без различия регистра; дата поиска задаётся как `08.02.2024`. Список содержит до 50 задач, отсортированных по дате и ID. Текстовый поиск фильтрует записи в Go до применения лимита и может просматривать всю таблицу.

## Локальный запуск

Нужен Go 1.24 или новее. Выполняйте команды из корня проекта:

```sh
go mod download
go run .
```

Адрес: http://localhost:7540/. Остановка — Ctrl+C.

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `TODO_PORT` | `7540` | Порт HTTP |
| `TODO_DBFILE` | `scheduler.db` | Путь к SQLite; родительский каталог должен существовать и быть доступен для записи |
| `TODO_PASSWORD` | пусто | Пароль; пустое значение отключает аутентификацию |
| `TODO_JWT_SECRET` | производный от пароля ключ | Отдельный секрет подписи JWT |

Пример запуска с паролем без записи секрета в команду:

```sh
read -r -s -p 'Пароль: ' TODO_PASSWORD
printf '\n'
export TODO_PASSWORD
export TODO_JWT_SECRET="$(openssl rand -hex 32)"
go run .
```

Пример рассчитан на Bash. Сохраните выбранный JWT-секрет вне репозитория, если токены должны действовать после перезапуска. Для доступа извне используйте HTTPS через обратный прокси: HTTP не шифрует пароль и cookie.

## API и авторизация

| Метод | Маршрут | Действие |
| --- | --- | --- |
| POST | `/api/signin` | Вход: JSON с полем `password`, ответ с `token` |
| GET | `/api/nextdate` | Следующая дата: параметры `now`, `date`, `repeat` |
| POST | `/api/task` | Создание задачи |
| GET | `/api/task?id=...` | Получение задачи |
| PUT | `/api/task` | Замена полей задачи; ID в JSON |
| DELETE | `/api/task?id=...` | Удаление |
| POST | `/api/task/done?id=...` | Завершение или перенос повторяющейся задачи |
| GET | `/api/tasks?search=...` | Список и поиск |

Когда задан `TODO_PASSWORD`, все методы `/api/task`, `/api/tasks`, `/api/task/done` требуют cookie `token`. Войдите через `/login.html`; фронтенд сохраняет cookie самостоятельно и при HTTP 401 перенаправляет на страницу входа. `/api/signin`, `/api/nextdate` и статика открыты.

JWT подписан HS256, действует 8 часов и содержит контрольную сумму пароля, но не сам пароль. Подпись и `exp` проверяются; смена пароля или секрета делает старые токены недействительными. При отсутствии отдельного секрета ключ зависит от пароля — это учебный режим; для развёртывания задайте случайный `TODO_JWT_SECRET` и стойкий пароль. Пароли и токены не логируются.

Пример создания при отключённой аутентификации:

```sh
curl -X POST http://localhost:7540/api/task \
  -H 'Content-Type: application/json' \
  -d '{"title":"Подвести итог","repeat":"d 7"}'
```

Ответ: `{"id":"1"}` (ID зависит от БД). Успешные редактирование, завершение и удаление возвращают `{}`; ошибки — `{"error":"..."}`. `nextdate` возвращает обычный текст.

## Тестирование

Тесты требуют запущенного сервера. Они могут изменять и очищать таблицу задач: используйте отдельную временную базу. Следующий пример запускается в Bash и отключает пароль только для тестового сервера:

```sh
TASK_TEST_DIR=$(mktemp -d)
export TODO_DBFILE="$TASK_TEST_DIR/scheduler.db"
export TODO_PORT=17540
export TODO_PASSWORD=
go run .
```

В другом терминале задайте те же `TODO_DBFILE` и `TODO_PORT`, затем выполните:

```sh
go test ./tests -v
go test ./...
go vet ./...
```

После проверки остановите сервер. `go test ./...` включает интеграционные тесты и также требует сервера.

Настройки `tests/settings.go`:

- `Port` — порт, если не задан `TODO_PORT`.
- `DBFile` — путь к БД относительно каталога `tests`, если не задан `TODO_DBFILE`.
- `FullNextDate` — расширенные проверки `w` и `m`, включены.
- `Search` — проверки поиска, включены.
- `Token` — действующий JWT для тестов при включённой аутентификации; тестовый клиент помещает его в cookie. Не сохраняйте токен в Git. Сервер и тесты должны использовать одну БД.

## Docker

```sh
docker build -t go-todo:latest .
mkdir -p data

docker run -d --name go-todo \
  --user "$(id -u):$(id -g)" \
  -p 7540:7540 \
  -e TODO_PORT=7540 \
  -e TODO_DBFILE=/data/scheduler.db \
  -e TODO_PASSWORD= \
  --mount "type=bind,src=$(pwd)/data,dst=/data" \
  go-todo:latest
```

Multi-stage сборка использует Go 1.24 и `CGO_ENABLED=0`; runtime — Alpine, по умолчанию пользователь UID/GID 10001. В приведённой команде `--user` использует UID/GID владельца каталога хоста, чтобы SQLite мог создавать БД и служебные файлы в bind mount. Выполняйте команду от обычного пользователя; для другого владельца каталога укажите соответствующие UID/GID. Не требуется делать каталог доступным для записи всем.

SQLite хранится в `./data` на хосте. Без bind mount контейнер использует собственный `/data`, и удаление контейнера уничтожит такую БД.

Для запуска с авторизацией задайте `TODO_PASSWORD` и `TODO_JWT_SECRET` в окружении хоста, затем вместо `-e TODO_PASSWORD=` передайте `-e TODO_PASSWORD -e TODO_JWT_SECRET`. Не добавляйте секреты в Dockerfile или Git.

```sh
docker logs go-todo
docker stop go-todo
docker start go-todo
```

После остановки и повторного запуска данные сохраняются. При пересоздании контейнера подключайте тот же каталог `data`. Для другого порта, например 8080, используйте `-e TODO_PORT=8080 -p 8080:8080`.
